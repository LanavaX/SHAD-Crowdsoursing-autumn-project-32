## Интерфейсы и инструкции

Интерфейсы реализованы в **Task Builder**. Поэтому их исходный код — JSON с компонентами `view`, `field` и `plugins`, а инструкции для исполнителей — HTML. Файлы `interfaces/*.json` точно совпадают с разобранным полем `task_spec.view_spec.config` соответствующего проекта в `settings/projects.json`. HTML извлечён из финального `public_instructions`, то есть это фактически сохранённая на платформе версия.

Чтобы посмотреть код, достаточно открыть эти файлы в репозитории. HTML можно скачать и открыть в браузере; иллюстрации загружаются по публичным ссылкам Google Drive. Для просмотра интерфейса в Яндекс Заданиях нужно выбрать редактор Task Builder, использовать соответствующий JSON и входной пример из `task_spec.view_spec.inputExample` полного экспорта. `task_spec.input_spec` и `output_spec` содержат определения входов/выходов. Исходные IDs навыков и пулов относятся к командному аккаунту; это снимок выполненной работы, а не команда создания новых оплачиваемых пулов.

## Как устроены допуск и проверка

- Bbox-экзамен: 7 примеров, проходной результат не менее 6/7. Из 12 завершённых попыток прошли пять исполнителей. После пилота добавлена отдельная практика точности, которую прошли два автора.
- Review-экзамен: 14 примеров, проходной результат не менее 12/14; восемь прошедших. Роли bbox и review взаимно исключены, автор не проверяет собственный ответ.
- Первичная разметка: одно изображение на странице, 0,75 ₽, перекрытие 1. Review: четыре основных случая и один контрольный на странице, 1 ₽, перекрытие 2.
- Для 396 исходных ответов получено по два независимых review. Четыре неопределённых/некорректных первичных ответа разобраны вручную. Разногласия, пропуски и границы рассмотрены отдельно.
- Команда вручную проверила 36 уникальных кадров и затем подтвердила 17 уточнений. Помощь Codex, модельные предложения, визуальный аудит и реальные человеческие голоса отмечены раздельно. Не у каждой окончательной версии есть два новых голоса после исправления; её путь принятия указан в provenance.

Подробный протокол находится в отчёте, полные фильтры и правила — в JSON пулов. Например: [основной bbox](settings/pools/6868546.json), [основной review](settings/pools/6868547.json). Контроли review сохранены в [settings/review-gold-curated.json](settings/review-gold-curated.json).

## Формат и воспроизведение golden set

В `golden.jsonl` одна строка на фото. Координаты `left`, `top`, `width`, `height` нормированы от 0 до 1; начало — левый верхний угол. Пустой список рамок означает подтверждённое отсутствие бабочек. `error=null` у всех 400 записей.

Целевой класс включает дневных и ночных бабочек, моль и бражников по уточнению консультации. Другие насекомые исключены. У обрезанного или закрытого объекта размечена видимая часть без достраивания скрытой. Используются рабочие JPEG из полного архива: исходные URL iNaturalist могут иметь другую геометрию. Группы manifest нужны для анализа результатов, их не передают моделям как подсказки.

После получения и распаковки архива из `DATASET.md`, из корня общего репозитория:

```bash
python -m pip install -r human_labeling/requirements-step2.txt
python human_labeling/reproduce/build_golden.py --frames /path/to/step2_delivery/images --output human_labeling/rebuilt
```

Замените `/path/to/step2_delivery/images` реальным путём. Каталог `rebuilt` должен отсутствовать. Команда проверит все изображения, SHA-256, размеры, геометрию и независимость исходных review, затем восстановит пять файлов: `golden.json`, `golden.jsonl`, `manifest.jsonl`, `provenance.json`, `validation.json`. Их эталонные версии лежат в `data/`. Зависимость Pillow относится только к этой части проекта; окружение моделей описывается в их собственных инструкциях.

Исторические поля `pending` внутри исходных версий сохранены для аудита; окончательное состояние приведено в `data/validation.json`. Перенос исходных файлов и извлечение полей документированы в `SOURCE_MAP.json`.

Этот каталог покрывает этап разметки. Код запуска трёх моделей, лидерборд, настройки экспериментов и автоматические предсказания для Контеста должны быть добавлены командой в общий репозиторий отдельно. Отчёт от 17 ноября описывает состояние именно на момент передачи датасета.
