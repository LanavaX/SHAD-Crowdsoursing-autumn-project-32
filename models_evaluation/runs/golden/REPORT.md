# Отчёт: выбор и обоснование модели (часть 3, финал — 18.11.2026)

Цепочка решений для защиты: **контракт данных → адаптация промптов → лидерборд 7 моделей →
однофакторные эксперименты → финальная конфигурация → посылка**. Все числа — на полном
golden set (400 фото, 330 рамок, 97 пустых), одинаковые фото для всех конфигураций.

## 1. Контракт целевого класса (отправная точка)

STEP2_REPORT разметки: *«по уточнению консультации целевой класс включает дневных и ночных
бабочек, моль и бражников»* — т.е. **все взрослые чешуекрылые (Lepidoptera)**; исключены
гусеницы, куколки, другие насекомые, тени. Это шире исходного текста задания (тот исключал моль).

Следствие для моделей: промпты обязаны просить мотыльков. Исходный Qwen-промпт
«no moths» прямо противоречил разметке → все базовые промпты переписаны
(`butterfly. moth.` / «butterfly or moth»). Проверено до основных прогонов, на данных.

## 2. Эволюция промптов (дым → golden)

На дымовом наборе (100 фото, псевдо-эталон консенсусом — только отладка) сравнили v1 (короткие)
и v2 (подробные) промпты: подробные **не дали систематического выигрыша** (у Qwen-4B +5 FP на
мотыльках — тогда ещё двойниках; артефакт `runs/smoke/prompts.md`). После уточнения контракта
мотыльки стали целью, и вопрос «поможет ли подробная инструкция» переоткрыт корректно —
как эксперимент D на настоящей разметке (см. п.4).

## 4. Однофакторные эксперименты (гипотезы записаны до запуска — experiments.md)

Задание требует хотя бы один эксперимент вида «меняем одну вещь — смотрим эффект». Мы провели
четыре. Каждому дали говорящее имя и код (A–D, им соответствуют секции в `experiments.md`).

**Три термина для понимания:**
- **Промпт** — текстовый запрос к модели. Детекторам достаточно списка слов («butterfly. moth.»),
  языковой модели (Qwen) нужна инструкция на английском («найди всех… ответь JSON…»).
- **Порог уверенности** — детектор выдаёт рамки с оценкой уверенности 0–1; порог решает, какие
  оставить. Низкий порог = много рамок (высокий Recall, но много лишних), высокий = мало.
- **NMS (подавление немаксимумов)** — автоматическое удаление дублей: если две рамки сильно
  перекрываются (IoU ≥ 0.5), оставляется одна, вторая выбрасывается.

### Эксперимент A «Классы-обманщики в запросе» (Grounding DINO tiny)

- **Что меняли**: в текстовый запрос добавили слова-обманщики `caterpillar. pupa.` (гусеница,
  куколка — то, что размечать НЕ нужно), а из ответа модели оставляли только рамки с метками
  «butterfly»/«moth». Логика: если модель умеет отличать названия, она перестанет рисовать
  рамки на гусеницах.
- **Гипотеза (до запуска)**: лишних рамок (FP) станет меньше, точность вырастет.
- **Что вышло**: F1 0.644 → 0.641 — **не сработало**. Модель не различает гусеницу и бабочку
  визуально, слова в запросе этому не учат.
- **Вывод для защиты**: отрицательный результат — это тоже результат; он обосновал, почему мы
  не стали усложнять запрос дальше.

### Эксперимент B «Настройка порога уверенности» (все детекторы)

- **Что меняли**: порог отсечения сомнительных рамок. У моделей «из коробки» он занижен
  (настроен на «лучше найти лишнее, чем пропустить») — мы прогнали порог от 0.05 до 0.60
  и выбрали лучший для каждой модели.
- **Гипотеза**: дефолтные пороги плодят лишние рамки, особенно на пустых фото; повышение
  порога поднимет F1.
- **Что вышло**: подтвердилось у всех. Пример OWLv2: дефолт 0.10 → оптимум **0.40**, F1 0.773,
  лишних рамок на пустых фото — 26 вместо сотен.
- **Вывод**: порог — самый дешёвый способ улучшения; рабочие пороги зафиксированы в конфиге.

### Эксперимент C «Удаление дублей рамок (NMS)»

- **Что меняли**: включали/выключали автоматическое схлопывание перекрывающихся рамок.
- **Гипотеза**: детекторы рисуют несколько рамок на одну бабочку (особенно если в запросе
  несколько слов), дубли — это чистые лишние рамки; NMS их уберёт, полнота не пострадает.
- **Что вышло**: подтвердилось драматически: **OmDet 0.572 → 0.794 (+0.222)**, Grounding DINO
  0.644 → 0.774 (+0.130, лишних рамок 180 → 52), при этом найденных бабочек почти не убавилось.
  У Qwen дублей нет — эффект +0.000…+0.009.
- **Вывод**: NMS обязателен для детекторов с многословными запросами; финалист (Qwen) в нём
  не нуждается.

### Эксперимент D «Подробная инструкция для языковой модели» (Qwen3-VL-4B)

- **Что меняли**: краткую инструкцию («найди бабочек и мотыльков, ответь JSON») заменили на
  развёрнутую: описали сложные случаи (бабочка может быть мелкой, дальней, замаскированной,
  перекрытой, обрезанной краем кадра; каждой бабочке — своя рамка) и что размечать нельзя
  (гусеницы, куколки, другие насекомые, тени).
- **Гипотеза**: языковая модель понимает естественный язык — подробное описание сложных случаев
  поднимет полноту на трудных фото, не добавив много лишних рамок.
- **Что вышло**: F1 0.947 → **0.959** — выросли И точность, И полнота.
- **Вывод**: это улучшение вошло в финальную конфигурацию.

## 5. Финальная конфигурация (config.WINNER)

**Qwen3-VL-4B-Instruct + подробный промпт (QWEN_PROMPT_DETAILED) + удаление точных
дублей рамок** — F1@0.5 = **0.961** (P 0.961, R 0.961, TP 317 / FP 13 / FN 13) на полном
golden set. Цепочка выбора: 0.959 (4B + подробный промпт, эксперимент D) > 0.955 (2B) >
0.947 (4B-база) — по правилу задания «лучшая F1@IoU 0.5, при равенстве более быстрая».
Пост-обработка: модель иногда печатает одну и ту же рамку дважды (на golden — 1 случай,
на экзамене — 4); точный дубликат — гарантированная лишняя рамка (одна бабочка сопоставляется
только с одной рамкой), поэтому дубликаты удаляются в `make_submission.py`. Это частный
случай NMS из эксперимента C (IoU=1.0) и даёт тот же эффект: FP 14→13 при TP 317 без
изменений. Порог не нужен (VLM без score). Версии зафиксированы: веса
`Qwen/Qwen3-VL-4B-Instruct`, transformers 5.19.0, bf16, детерминированная генерация
(do_sample=False, max_new_tokens=1024), координаты из bbox_2d /1000 → нормализация 0–1.

Ожидаемые очки контеста по шкале задания: int(min(10, 10×(0.961+0.3))) = **10 из 10**
(при переносе качества на экзамен; запас до порога 0.7 — 0.26).

## 7. Экзамен: прогон и перекрёстная проверка

400 фото экзамена скачаны по URL из `dataset.jsonl` (у 52 старых фото расширение `original.JPG`
заглавными — учтено; 7 фото имели EXIF-поворот — применён `exif_transpose` до инференса).
Финальная конфигурация дала **193 фото с рамками / 207 пустых** (после удаления 4 точных
дублей — 204 рамки).

Перекрёстная проверка доверия: **qwen3_vl_2b (базовый промпт) независимо выдал ровно те же
207 пустых фото**. На 193 остальных у каждой рамки 2B нашлась пара у 4B с IoU≥0.5; полное
посимвольное совпадение числа рамок — на 180/193 (на 13 фото 4B нашла по 2 бабочки против
одной у 2B — 4B чувствительнее, не противоречие). Третья, архитектурно чужая модель —
owlv2_base @ 0.40 — независимо считает пустыми 190/400, срабатывает лишь на 26 из 207
«пустых» (на golden её ложный фон на пустых — 26/97, т.е. это её норма, а не признак
спрятанных бабочек) и подтверждает 184/193 непустых. Три модели разных семейств сходятся:
состав экзамена действительно ~50% негативный (в golden — 24%), а не артефакт консервативности.

`submission.jsonl`: 400 уникальных photo_id (≡ dataset.jsonl), `boxes` — список, `error: null`,
32 КиБ ≤ 5 МиБ. Все пункты чек-листа задания выполнены.
